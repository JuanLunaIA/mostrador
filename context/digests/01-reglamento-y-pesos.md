# Digest 01 — Reglamento y pesos

**Fuente:** https://donwebday.com/hackaton/ (Reglamento "Del problema al servidor")

## Ventana

| Hora | Hito |
|---|---|
| 15:15 | Revelación de la consigna + apertura |
| 15:15–18:30 | Desarrollo y deploy a producción |
| 18:30–19:00 | Cierre de entregas y deliberación |
| 19:00–19:15 | Premiación en Main Stage |

Tiempo neto de construcción: **3 h 15 min**.

## Entregables obligatorios (§3.5)

1. **URL pública** del proyecto desplegado en el Cloud Server provisto.
2. **Repo público de GitHub** (o acceso otorgado al jurado).

## Regla de exclusión (§3.7)

> "El despliegue funcionando con URL pública es condición excluyente para participar de la evaluación."

Un proyecto ambicioso sin deploy saca **cero**. Un proyecto simple online compite.

## Anti-cheat (§3.2–3.6)

- El historial de commits debe reflejar desarrollo **durante** el evento.
- Repo con commits previos al evento = descalificación.
- No se permite código de proyecto escrito antes.
- Librerías y servicios de acceso público **sí** están permitidos.
- No colaboración ni asistencia externa.

## Proveído por la organización (§4.1)

- Espacio de trabajo individual, wifi, electricidad.
- **Un Cloud Server de DonWeb** por participante para el deploy final.
- **Una API key compartida de OpenAI**, sólo para la IA dentro del producto.
- §4.2: uso indebido o post-evento de cualquiera de los dos = descalificación inmediata.

## Pesos de evaluación

| Criterio | Peso |
|---|---|
| Que la solución resuelva la problemática **de verdad** | **35%** |
| Profundidad y completitud de la solución | **30%** |
| Calidad de la IA integrada | **25%** |
| Presentación al jurado | **10%** |

Lema en la landing: **"No gana el que más código escribe: gana el que mejor resuelve."**

## Prerrequisito duro

Saber desplegar a un servidor cloud. *"No se enseña durante el evento."* Es el único.
